# Vetra Portal

قالب مستقل، راست‌چین و بهینه‌شده وردپرس برای سایت شرکتی **گروه ساختمانی و مهندسی وترا** (`portal.vetragroup.ir`).

## امکانات

- طراحی شرکتی تمیز با ناوبری افقی، Hero، آمار، خدمات، پروژه‌ها و CTA
- پشتیبانی کامل از حالت روشن / تیره و هماهنگی با سیستم‌عامل
- تنظیمات بصری جامع از طریق Customizer (رنگ‌ها، فونت، محتوا، تماس)
- واکنش‌گرا برای موبایل، تبلت و دسکتاپ
- Elementor به‌عنوان صفحه‌ساز اصلی قالب و پشتیبانی از ElementsKit Lite
- فرم تماس و فرم‌های حرفه‌ای با Gravity Forms (نیازمند لایسنس رسمی)
- مخزن داده مستقل «پروژه‌ها» برای استفاده مشترک قالب و افزونه‌های آینده؛ بدون CPT، پست یا برگه
- نقش‌های آماده پروژه و امکان ساخت/ویرایش نقش سفارشی
- ثبت و ویرایش پروژه از پیشخوان یا شورتکد برای کاربران مجاز
- PWA اختیاری همراه manifest، Service Worker با scope ریشه و پیشنهاد نصب
- پیام کوکی قابل تنظیم، حالت تعمیر/به‌روزرسانی و الگوهای Gutenberg
- لوگو، favicon و تصاویر برند پیش‌فرض (ساختمان، فضای داخلی) همراه قالب
- فعال‌سازی/غیرفعال‌سازی مستقل هدر، فوتر، Hero، آمار، خدمات، درباره ما، پروژه‌های منتخب و CTA

## نصب

1. فایل ZIP رسمی را از بخش Release نصب کنید؛ ساختار ZIP شامل پوشه استاندارد `vetra-portal/` است.
2. قالب را از مسیر **نمایش > پوسته‌ها** فعال کنید.
3. برای شخصی‌سازی به **نمایش > سفارشی‌سازی > هویت شرکتی وترا** بروید.
4. یک صفحه ثابت برای خانه انتخاب کنید تا `front-page.php` نمایش داده شود.
5. برای بازسازی پیوندهای یکتا، یک‌بار به **تنظیمات > پیوندهای یکتا** بروید و ذخیره کنید.

## افزونه‌های پیشنهادی

قالب بدون افزونه هم کامل کار می‌کند. Elementor صفحه‌ساز اصلی توصیه‌شده است. از بخش **نمایش > افزونه‌های وترا** موارد زیر را مدیریت کنید:

- **Elementor** — صفحه‌ساز بصری
- **ElementsKit Lite** — ویجت‌های تکمیلی Elementor
- **Gravity Forms** — فرم‌ساز حرفه‌ای با ZIP رسمی و لایسنس خریداری‌شده

## پروژه‌ها و دسترسی کاربران

- از منوی مستقل **پروژه‌ها > افزودن پروژه** اطلاعات اصلی پروژه را در جدول اختصاصی قالب ثبت کنید؛ این داده‌ها پست، برگه یا CPT وردپرس نیستند.
- فیلدهای اصلی در گروه‌های جداگانه فرم: نام پروژه، نام کارفرما، کاربری، نوع قرارداد، شماره قرارداد، پیمانکار، تاریخ شروع قرارداد، مدت قرارداد، مبلغ اولیه پیمان، ناظر پروژه، مدیر پروژه، سرپرست کارگاه، آدرس پروژه، آدرس کارفرما، شماره پرونده شهرسازی و پلاک ثبتی فرعی/اصلی.
- از مسیر **کاربران > نقش‌های وترا** نقش جدید بسازید یا سطح دسترسی نقش‌های پروژه را ویرایش کنید.
- برای فرم سمت کاربر از شورتکد `[vetra_project_form]` استفاده کنید.
- برای نمایش پروژه‌های منتشرشده از `[vetra_project_list]` استفاده کنید.
- قابلیت `vetra_submit_projects` فرم را نمایش می‌دهد و `vetra_create_projects` اجازهٔ ایجاد می‌دهد؛ این دو مجوز مستقل‌اند.

### API و شناسه‌های پایدار فیلدها

فرم داخلی حفظ شده است؛ جدول مستقل و ساختار ذخیره‌سازی فعلی با نگاشت مستقیم Gravity Forms سازگار نیست و Gravity Forms نیز افزونهٔ تجاری جداگانه‌ای است. افزونه‌ها برای خواندن داده از `vetra_project_get( $id )` یا `vetra_project_get_field( $id, 'field_id' )` استفاده کنند. خواندن پروژه‌های تأییدنشده از API فقط برای کاربر دارای مجوز ویرایش همان پروژه یا مدیریت پروژه مجاز است. از خواندن مستقیم جدول خودداری کنید.

شناسه‌ها همان نام‌های ثابت ستون/فیلد هستند: `project_name`, `client_name`, `project_usage`, `contract_type`, `contract_number`, `contractor`, `contract_start`, `contract_duration`, `initial_amount`, `project_supervisor`, `project_manager`, `site_supervisor`, `project_address`, `client_address`, `urban_file_number`, `registry_sub`, `registry_main`, `category`, `summary`, `description`. فهرست برنامه‌ای در `vetra_project_field_ids()` در دسترس است. این شناسه‌ها قرارداد API قالب هستند؛ هیچ گزینهٔ وضعیت تأیید در فرم سمت سایت نمایش داده نمی‌شود.

قابلیت‌های نقش: `vetra_submit_projects` دسترسی به رابط فرم، `vetra_create_projects` ایجاد، `vetra_edit_own_projects` و `vetra_edit_all_projects` ویرایش، `vetra_approve_projects` تغییر وضعیت و `vetra_delete_projects` حذف است. پیشخوان از کاربران فاقد `manage_options` دور نگه داشته شده است.

### قالب صفحه

در ویرایش برگه، از بخش «ویژگی‌های برگه > قالب» گزینهٔ «وترا: تمام‌عرض» را انتخاب کنید. الگوی Elementor Canvas نیز همچنان از خود Elementor قابل انتخاب است. این قالب فقط پوستهٔ محتوای صفحه را تمام‌عرض می‌کند و نصب Elementor را الزامی نمی‌سازد.

### محدودیت‌های پیاده‌سازی

### نقش‌ها، دسترسی صفحه و برگه‌های نمونه

- از **کاربران > نقش‌های وترا** نقش بسازید و مجوز فرم، ایجاد، ویرایش و مدیریت پروژه را مستقل تعیین کنید. از **کاربران > حذف نقش سفارشی** فقط نقش‌های سفارشی خودتان را حذف کنید؛ نقش‌های پایهٔ پروژه حذف‌پذیر نیستند.
- در ویرایش هر برگه، جعبهٔ «دسترسی بر اساس نقش» را تنظیم کنید. محدودیت برگه در رندر سمت سرور، REST API و منوی وردپرس بررسی می‌شود.
- برای محدودکردن بخشی از محتوا از `[vetra_restrict roles="subscriber,vetra_project_editor"]محتوای محدود[/vetra_restrict]` استفاده کنید. فهرست نقش‌ها را با شناسهٔ نقش جدا کنید.
- از **نمایش > تنظیمات وترا** پیام کوکی، پیوند برگهٔ قوانین، جایگاه پیام و حالت تعمیر/به‌روزرسانی را تنظیم کنید. پذیرش پیام کوکی فقط در مرورگر ذخیره می‌شود و سامانهٔ مدیریت رضایت یا مسدودسازی کوکی‌های تحلیلی/تبلیغاتی نیست.
- نمونه‌برگه‌ها در همان صفحه با عملیات صریح ایجاد/بازسازی یا حذف می‌شوند؛ فعال‌سازی پوسته به‌تنهایی محتوای سایت را تغییر نمی‌دهد. بازسازی فقط برگه‌هایی را به‌روزرسانی می‌کند که نشانگر `_vetra_sample_key` پوسته را داشته باشند.
- الگوهای Gutenberg در inserter با دستهٔ «وترا: صفحات شرکتی» قابل استفاده‌اند. پوسته classic است و Site Editor برای ویرایش قالب کامل سایت فعال نیست؛ Elementor برای صفحه‌ها قابل استفاده است.

### هویت، فونت و آیکن

لوگوهای روشن/تیره و اصلی در **سفارشی‌سازی > هویت شرکتی وترا > هویت برند** هستند؛ favicon از کنترل استاندارد **هویت سایت > آیکون سایت** وردپرس می‌آید. حق‌نشر پایین فوتر نیز در بخش «تماس و CTA» قابل تغییر است و `{year}` با سال میلادی جاری جایگزین می‌شود. چندین هدر/فوتر قابل انتخاب برای هر برگه هنوز وجود ندارد.

پوسته فایل فونت فارسی همراه خود ندارد؛ انتخاب‌های موجود از فونت‌های نصب‌شده در سایت استفاده می‌کنند و بارگذاری اختیاری از CDN دارند. در صورت میزبانی محلی فونت، مجوز و منبع همان فایل را جداگانه بررسی و ثبت کنید. آیکن‌های درون‌خطی SVG پوسته محدودند و سامانهٔ بارگذاری آیکن اختصاصی هنوز ندارد.

### PWA و یکپارچه‌سازی

PWA از **سفارشی‌سازی > وب‌اپ PWA** روشن/خاموش می‌شود. نام، رنگ، آیکن، متن پیشنهاد نصب، فعال‌بودن پیشنهاد و تأخیر آن را همان‌جا تنظیم کنید. اجرای PWA به HTTPS و آیکن معتبر نیاز دارد؛ پس از تغییر پیوندهای یکتا اگر endpointها کار نکردند یک‌بار آن‌ها را ذخیره کنید. هنگام خاموش‌شدن، پیشنهاد پنهان می‌شود و Service Worker خود پوسته unregister می‌شود.

وضعیت افزونه‌های پیشنهادی در **نمایش > افزونه‌های وترا** نمایش داده می‌شود. Gravity Forms نیازمند ZIP رسمی و لایسنس است و اتصال مستقیمی به مخزن پروژه‌های پوسته ندارد. هیچ اتصال زندهٔ AI یا MCP پیاده‌سازی نشده است؛ برای کلید آینده از `wp-config.php` یا secret manager سمت سرور استفاده کنید، هرگز آن را در تنظیم پوسته، مرورگر یا مخزن قرار ندهید. اتصال MCP نیازمند سرویس و زیرساخت مستقل سرور است.

## Customizer

تنظیمات در پنل **هویت شرکتی وترا** بر اساس کاربرد گروه‌بندی شده‌اند. پالت رنگ نسخه ۲.۰ و پس‌زمینه جامع کاملاً مستقل هستند؛ پس‌زمینه تا زمان فعال‌سازی هیچ تغییری در ظاهر ایجاد نمی‌کند.

- ظاهر پایه و رنگ‌ها: حالت روشن/تیره، پالت رنگ و فونت
- پس‌زمینه جامع: رنگ، گرادیان، تصویر، الگو و Overlay با فعال‌سازی مستقل
- منوی موبایل: منوی کشویی/برگه پایین و نوار چسبان پایین موبایل
- نوار کاربر: آواتار و فهرست کاربران در صفحات منتخب
- وب‌اپ PWA: manifest، Service Worker و تنظیمات نصب اپ

## ساختار قالب

- `front-page.php` — صفحه اصلی شرکتی
- `index.php` — آرشیو/وبلاگ
- `page.php` — صفحه ثابت
- `404.php` — صفحه یافت نشد
- `header.php` / `footer.php` — هدر و فوتر
- `assets/css/corporate.css` — سیستم بصری اصلی
- `assets/css/customizer.css` — استایل پنل Customizer
- `assets/js/corporate.js` — تعویض حالت روشن/تیره، منوی موبایل، reveal
- `assets/js/service-worker.js` — Service Worker اختیاری PWA
- `assets/images/` — لوگو، favicon و تصاویر برند پیش‌فرض
- `inc/customizer.php` — تنظیمات Customizer
- `inc/projects.php` — جدول مستقل پروژه‌ها، پنل مدیریت، نقش‌ها و شورتکدهای پروژه
- `inc/helpers.php` — توابع کمکی
- `inc/plugin-manager.php` — مدیریت افزونه‌های رایگان
